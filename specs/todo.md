# Открытые вопросы и TODO

Документ собирает незавершённые задачи и вопросы из материалов каталога `specs/`. Он не заменяет исходные требования и технологические решения, а служит единым списком дальнейшей работы.

Приоритет отражает влияние вопроса на ближайшую разработку:

- **Высокий** — необходимо решить до начала соответствующего этапа или в ходе создания первого рабочего прототипа.
- **Средний** — желательно решить в ходе разработки MVP; вопрос не должен блокировать начальный прототип.
- **Низкий** — относится к возможному развитию проекта или к технологиям, не нужным для первой версии.

Статусы и решения следует синхронизировать с профильными документами. После закрытия пункта нужно обновить этот список и, если требуется, исходный документ.

**Источники:**

- [Исходные требования и заметки проекта (scratchpad.md)](scratchpad.md)
- [Выбор языка программирования и связанные технологические решения (technology-decisions.md)](technology-decisions.md)

## Высокий приоритет

### Инструменты разработки

- [ ] Выбрать компилятор и toolchain для Windows: MSVC, Clang/LLVM, MinGW или другой вариант.
- [ ] Выбрать систему сборки: CMake, MSBuild или другой инструмент.
- [ ] Проверить поддержку выбранным toolchain необходимых возможностей C++23, включая используемые возможности стандартной библиотеки.

### Определение раскладки и поведение приложения

- [ ] Определить способ обнаружения смены раскладки: периодический опрос или системные уведомления Windows.
- [ ] Проверить, можно ли надёжно получать уведомления о смене раскладки активного окна и насколько быстро они позволяют обновлять индикатор.
- [ ] Проверить корректность определения раскладки именно активного окна при переключении между приложениями и окнами.

### Тестирование базового прототипа

- [ ] Определить способ тестирования Win32-ресурсов и графического оверлея.
- [ ] Определить минимальный набор проверок корректности позиционирования, отображения поверх приложений и отсутствия перехвата кликов.

## Средний приоритет

### Правила разработки и диагностика

- [ ] Определить политику исключений и правила применения `std::expected` для обработки ошибок.
- [ ] Закрепить правила статического анализа и форматирования кода.
- [ ] Проверить доступность и совместимость AddressSanitizer и других выбранных средств диагностики в целевых конфигурациях.

### Поддерживаемые версии Windows

- [ ] Решить, должна ли Windows 7 быть обязательной платформой, дополнительной целью или не поддерживаться.
- [ ] Если Windows 7 станет целевой платформой, подобрать и проверить совместимую комбинацию компилятора, Windows SDK, runtime и используемых Win32 API.

### Настройки приложения

- [ ] Определить способ редактирования настроек: конфигурационный файл или графический интерфейс.
- [ ] Определить формат и расположение файла настроек, если будет выбран конфигурационный файл.
- [ ] Определить, какие параметры приложения должны быть доступны пользователю.

### Интеграция с Windows

- [ ] Реализовать запуск приложения при входе пользователя в Windows (автозапуск) и определить подходящий механизм регистрации автозапуска.

## Низкий приоритет

### Дополнительные варианты работы с курсором

- [ ] Решить, нужно ли в будущем поддерживать оба режима: отдельный индикатор рядом с системным курсором и замену системного курсора.

## В дальний ящик

### Возможная Linux-версия

- [ ] Решить, оформлять ли Linux-вариант как отдельный репозиторий или как отдельный backend в текущем проекте.
- [ ] Изучить варианты интеграции с KDE/KWin и Wayland, включая API эффектов KWin, опрос положения мыши и D-Bus.
- [ ] Проверить техническим прототипом, как получать положение курсора и отображать индикатор в целевой среде Arch Linux + KDE Plasma + Wayland.
- [ ] Определить границы общей платформонезависимой логики и платформенных реализаций Windows/Linux.
